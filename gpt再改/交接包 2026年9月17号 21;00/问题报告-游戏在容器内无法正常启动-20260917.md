# 问题报告：目标游戏在容器环境内无法正常启动（进不去）

> 日期：2026-09-17 21:00
> 环境：Android 12 / arm64 真机（免 Root）· 容器：VirtualApp14 定制宿主（com.carlos.multiapp，debug 构建）
> 目标应用：`com.tencent.tmgp.pubgmhd`（UE4 引擎，含 `libtersafe` 保护库）
> 本报告只描述**一个技术问题**：**游戏在容器内启动后反复重建、黑屏、无法进入**。
> 目标读者：只负责修复此问题的工程师。

---

## 一、现象

1. 从容器内以 `startActivity` 方式启动游戏后：
   - 游戏进程**能被拉起**（日志可见 `Binding application`、`libtersafe.so`（tss_sdk_init）初始化、:443 联网）；
   - 但**进程反复重建**：秒级出现新 pid（实测样本：3743 → 4482 → 7678 → 7737 → 9904 → 12546 → 12660 → 12752 …）；
   - 界面**持续黑屏**，永远到不了游戏画面/登录界面。
2. **对照**：同容器内的另一个应用（`com.tencent.xriver`）运行稳定（不重建、不黑屏）。
   → 容器底座总体可用；问题与**该游戏自身的特性**（UE4 大 native 库、多 dex、Tinker、保护库）相关。

**要点**：`SandHook.initNative` 的 **native 实现缺失**（找不到对应 JNI 符号）。该“噪音”在官方发行版同样存在（历史记录），但在**该游戏**的 bind 路径上它升级为**致命阻断**。

## 三、已做的缓解（运行时插桩，位于容器宿主 assets/pc_hook.js）

| 补丁 | 作用 | 状态 |
|---|---|---|
| `SandHook.initNative` → 恒返回 `true` | 让类初始化成功 | 已生效（guest 日志：`SandHook.initNative -> true`） |
| `PineXposed.init` → try/catch 包裹 | 吞异常继续 | 已生效（`PineXposed.init wrapped`） |
| `ContextFixer.fixContentProvider` → try/catch 包裹 | 吞 bind 中断异常 | 已生效（`ContextFixer.fixContentProvider wrapped`） |

**局限**：插桩装载时机（等容器引擎就绪后）**晚于**游戏进程的“首次初始化失败”；ART 会缓存类初始化失败（后续均抛 `NoClassDefFoundError`）——因此**需要更早/更根本的修复**。

## 四、修复方向（建议，供接手人选择）

1. **补齐 SandHook native 实现**（根因候选）：
   - 检查宿主 APK `lib/arm64-v8a` 是否包含 SandHook 的 native 库、`SandHook.initNative` 的 JNI 注册路径是否完整；
   - 若官方设计上该路径应被“跳过”（实际 hook 由 shadowhook/vbox 承担），则应在 **PineXposed.init 内部**吞掉该失败（改引擎源码并重新构建宿主）。
2. **让 ContextFixer 的 hook 失败不致命**（引擎侧修复）：把 `fixContentProvider` 中的 `findAndHookMethod` 包 try/catch。
3. **调整容器装载时序**（若维持运行时修复路线）：让插桩早于 `VirtualCore.initialize` 装载——注意历史上有“过早装载与引擎竞争导致 SIGSEGV”的记录（见 `docs/02-问题清单与错误结果实录.md`），需谨慎验证。
4. **（备选）确认游戏是否对虚拟环境有主动检测**：若黑屏为“检测到容器”所致，需要在容器层做针对性兼容（需进一步取证：对比“能出画面”的基线日志）。

## 五、验证方法（改完必跑）

```bash
# 1) 进程稳定性（pid 是否还在变化）
adb shell "ps -A | grep tmgp"

# 2) 关键异常是否消失
adb shell "logcat -d | grep -E 'SandXposed|PineXposed|ContextFixer'"

# 3) 画面（应能出游戏画面，至少稳定前台）
adb shell screencap -p /sdcard/g.png && adb pull /sdcard/g.png
```

**判据**：游戏 pid 稳定（≥60s 不变）+ 日志中上述异常不再出现 + 屏幕出现游戏画面。
