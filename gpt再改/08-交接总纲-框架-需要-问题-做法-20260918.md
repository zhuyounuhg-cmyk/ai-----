## 一、项目框架（列举）

### 1.1 运行时架构（真机 → 容器 → guest）

```
真机 iQOO Neo3（V1981A · Android 12 · arm64 · 免 Root · adb e5e1ac3b）
 └─ 容器宿主：com.carlos.multiapp（VirtualApp14 定制版，debug 签名）
      ├─ 引擎层
      │    ├─ lib-release-android12-v4.aar（Android 12 适配引擎 v4）
      │    ├─ 补丁（PatchPineXposed.java 生成）：
      │    │    - PineXposed.init / fixPendingIntentFlags / initForXposed：API≥31 直接跳过
      │    │    - ContextFixer.fixContentProvider()：API≥31 直接跳过
      │    │    - libvbox.so：libtersafe.so 匹配名 → 不可命中的占位名（禁用安全库拦截）
      │    └─ PcApp/PcGadget/PcGadgetPolicy（宿主接入层，白名单装载）
      ├─ 插桩层
      │    ├─ Frida Gadget（script 模式，on_change=ignore）→ files/pc_hook.js
      │    └─ pc_hook.js：请求回放（离线）、校验对照、直驱（OpenImgui / 拉起游戏）
      └─ guest（容器内应用）
           ├─ com.tencent.xriver            主应用（外层登录 → 二级页 → ①窗口 → ②进游戏）
           ├─ com.qihoo.magic               分身大师（xriver 检查链依赖，检查通过用）
           └─ com.tencent.tmgp.pubgmhd      游戏（UE4+libtersafe；**当前卡在启动稳定性**）

旁路对照（真机原生环境，不在容器内）：
  - 真机 com.tencent.xriver / com.qihoo.magic / 游戏本体
  - 「和平精英启动器」类入口 —— 证明“游戏在原生环境可正常启动”
```

### 1.2 关键链路（目标：登录稳定 → 面板窗口 → 开始对局）

```
外层登录（假回包 + 本地摘要对照）→ 二级页
  → 点「①」→ 二级认证回放（kmlogin&app=54010，四字段）→ 直驱调 OpenImgui（面板窗口出现）
  → 点「②」→ AppEnterActivity → 检查链（分身大师/自签名/meta/游戏包）→ 直驱拉起游戏
  → 目标：游戏稳定越过登录界面 → 开始对局
```

## 四、怎么搞（路线与步骤）

### 路线 A（主推）：继续修容器兼容性
1. **修 AttributionSource**（Binder/Provider 代理层）：
   - 打印一次完整的 `AttributionSource` 对象（字段逐项），确认“来源 UID 10002”的构成；
   - 在容器代理层归一化：**UID = 实际发起进程（容器 UID）**、**package 与 UID 映射一致**；
   - 修完先静态验证（不改动其他行为），再真机验证。
2. **真机验证（150 秒采集）**，判据（三项）：
   - **登录稳定**（游戏越过登录界面、进程 PID 稳定不重建）；
   - **面板窗口**（可调出，浮层正常）；
   - **开始对局**（进入对局/开始游戏按钮流程）。
3. **证据归档**：采集目录（`07-.../device-validation-*`）含：进程采样（ps×N）、maps、logcat 前后、exit-info、截图、summary.json。

### 路线 B（备选/对照）：真机原生
- 用「启动器/桌面」在**真机**启动游戏作为“能启动”的基线；
- 用于对照容器问题（身份/归因/环境），不替代容器验证。

### 常用命令速查
```powershell
# 装机核对
adb -s e5e1ac3b shell pm path com.carlos.multiapp
adb -s e5e1ac3b shell sha256sum <path>      # 与候选 APK 哈希比对
# 进程与前台
adb -s e5e1ac3b shell "ps -A | grep -E 'multiapp|tmgp|xriver'"
adb -s e5e1ac3b shell dumpsys activity activities | findstr mResumedActivity
# 日志（关键字）
adb -s e5e1ac3b logcat -d -v threadtime | findstr /C:"VA-Compat" /C:"AttributionSource" /C:"Fatal signal" /C:"SIGBUS"
# 证据采集（项目脚本）
.\07-compatibility-review-20260917\Collect-Compatibility.ps1 -Adb <adb> -Serial e5e1ac3b -Apk <apk> -OutputDirectory <dir> -ObserveSeconds 150 -CaptureMaps
```

### 验收判据（写死，别放宽）
- **PID 稳定 ≥60 秒**（无同因重建）；
- **日志**：无归属不明的 native 崩溃 / 无 UID 不一致报错；
- **画面**：能过登录界面；能开始对局；
- 三项**缺一不可用“尚未执行”**，不得写“通过”。

## 五、常见问题（给接手人）

**Q1：为什么“和平精英启动器/桌面”能启动游戏，容器里不行？**
- 原生环境：游戏以**普通应用身份**运行（真 UID + 真包名），所有自检/归因天然一致 → **一启就起**；
- 容器环境：游戏跑在**虚拟化层**里（宿主 UID 10499 承载 guest 身份）——身份/归因/环境需逐层代理；
  老引擎与 Android 12 的强制机制冲突，需要逐层修复（v1→v4 已修三层，剩下归因层）。

**Q2：改哪里、不能改哪里？**
- 能改：容器引擎（aar/字节码补丁）、宿主代码（com.pc.*）、插桩脚本（pc_hook.js）、构建/采集脚本；
- 不能改：目标应用 APK、游戏、分身大师、系统；不重打包、不绕过安装确认。

**Q3：验证时必须注意什么？**
- 新旧日志用**时间戳/PID**区分，不用旧崩溃“冒充”本轮结果；
- 采样**不足以**证明“没有重启”？——写明局限（如 summary.json 的 limitations），别过度声明；
- 装完先核对 **SHA-256** 再谈结论。
