## 一、红队已证实的手段（攻击面总览）

| # | 手段 | 现状 | 说明 |
|---|---|---|---|
| A1 | 免 Root 容器 + 运行时插桩（Frida Gadget） | 通过 | 客户端零对抗：无插桩检测、无完整性自检 |
| A2 | 请求/响应离线替换 | 通过 | UrlPost 出口替换 + decryRC4 注入回包 |
| A3 | 本地校验「窗口对照替换」 | 通过 | 摘要校验前替换结果（外层登录的关键突破口） |

## 二、加固点清单（按优先级）

### P0 · 认证判据上移服务端（最关键）
- **现状问题**：外层「登录成功」的闸门是**本地 MD5 摘要比对**——红队在运行时替换比对结果即可过（A3）。
- **加固**：判定必须依赖**服务端一次性凭据**（nonce / challenge / 服务端签名），客户端只透传、不能本地复现；本地比对仅作辅助、不作为放行依据。

### P1 · 防重打包（已有，保持并扩展）
- 现有 `自身签名 == 0CEC88278D413889FBDB051F82E3A65B` 闸门（b 路径）是**好例子**——重打包必挂，建议：
  - 扩展到二级认证链路的全部关键入口；
  - 校验点分散 + 结果服务端复核（避免单点被 hook 覆盖）。

### P2 · 防插桩 / 反调试
- 增加运行时检测：Frida 特征（命名管道、gadget 模块、线程名）、ptrace 自检、maps 扫描、LD_PRELOAD 监控；
- 关键校验逻辑下沉 native / 白盒化，避免纯 Java 层可被一把 hook。

### P3 · 环境校验服务端化
- 现状：分身大师（版本/官方证书）、`magic-meta.json`、游戏包等**全部本地比对** → 容器/fake 可满足（A4）。
- **加固**：这些环境信息应（连同设备指纹）**上报服务端交叉验证**，服务端建立会话后再下发「可进入游戏」的一次性令牌。

### P4 · 关键动作令牌化
- `OpenImgui` / 进入游戏等关键动作，前置校验「服务端一次性令牌」；令牌与设备/会话绑定、短时效、用后即焚。

### P5 · 运行时完整性
- Dex2C 之外增加**运行时自检**（代码段/关键方法校验、定期抽查），检测运行时替换（A2/A5）。

## 三、验收矩阵（回归对照用）

| 红队手段 | 当前结果 | 加固后目标 |
|---|---|---|
| A2 假回包替换 | 通过（跳二级页） | 失败（服务端凭据不符） |
| A3 摘要对照替换 | 通过 | 失败（无可替换的本地判据） |
| A4 环境伪造 | 通过（检查全过） | 失败（服务端环境复核） |
| A5 动作直驱 | 通过（游戏拉起/辅助直调） | 失败（缺一次性令牌） |
| A1 插桩本身 | 通过 | 检测并上报/降级 |
